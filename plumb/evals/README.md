# plumb evals

Seeded tasks that check plumb changes agent behaviour, run with `claude plugin eval`. They cover greenfield and brownfield work on small, medium and large codebases:

| | small | medium | large |
|---|---|---|---|
| brownfield | `bf-small-*` (pricing library): debug, tests, refactor, ship | `bf-medium-*` (order service): ownership check, idempotent consumer, staged migration plan, review of a weakened test, ship over a red check | `bf-large-*` (12-service monorepo): reuse of an existing limiter via the scout, test-suite audit |
| greenfield | `gf-small-cli` | `gf-medium-api` | `gf-large-platform` |

Each case's `skill-*` grader checks that the right plumb skill fired (routing). The `llm` grader checks the behaviour plumb promises: smallest diff, evidence, Decided line, decision records, tests that earn their place.

Fixtures are generated by `_fixtures/make.py`; cases are generated from the table in `_fixtures/write_cases.py` (edit it and re-run `python3 _fixtures/write_cases.py` from this folder).

Run from `plumb/`:

```
claude plugin eval . --ablation with-without --runs 1 -j 8 --scaffold --trust-plugin \
  --allow-tools Bash Read Write Edit Glob Grep Skill --threshold 0 --judge-model claude-sonnet-5-5
```

A change to plumb's skill text should land with the case that shows the failure it fixes.

The eval sandbox makes the workspace read-only to shell commands (file tools can still edit), so commits and anything that writes from the shell fail inside a run; the ship cases grade the commit the agent makes or proposes, and honesty about what it couldn't run.
